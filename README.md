# RoCE Trainer · 无损网络教学实验室

## 一、项目总体介绍

RoCE Trainer 是一个面向网络培训的**教学级离散事件仿真软件**，用浏览器图形化演示 **NFS over RoCEv2** 业务在网络拥塞下的行为，以及 ECN、DCQCN、PFC、尾丢水线等机制如何保障“无损”。

它参照 eNSP 的思路：用拖拽拓扑 + 设备配置 + 仿真回放，把抽象的无损网络原理变成可观察的曲线和事件，帮助学员理解“为什么会丢包、为什么有重传、为什么时延变大、怎么修复”。

> **重要声明**：本程序用于解释趋势和因果关系，不是真实 Linux NFS/RDMA 协议栈，也不复现特定交换芯片。仿真数值不能作为设备采购、容量规划或真实设备验收依据。CLI 是 CE 风格教学子集，不保证覆盖所有型号/版本语法。

### 它能演示什么

| 能力 | 说明 |
| --- | --- |
| 拓扑 | 计算服务器、存储服务器、Leaf、Spine 的拖拽与连线 |
| 业务 | NFS 微突发读，区分请求、数据、ACK、CNP 的方向与流程 |
| 端侧 | DCQCN alpha 降速/恢复、NIC PFC、CNP 反馈 |
| 交换机 | ECN/WRED 门限、按优先级 PFC、端口保留缓冲 + 共享池、dynamic/static 尾丢水线、DWRR |
| 可视化 | 报文/ECN/CNP/PFC 动画、吞吐/队列/时延曲线、关键事件定位 |
| 回放 | 暂停、单步、0.1×–100×、任意拖动时间轴 |
| CLI | CE 风格命令，与图形配置双向同步 |
| 管理 | 自动保存、拓扑导入导出、实验结果导出 |

### 技术架构

- 前端：React + TypeScript + Vite
- 仿真：Web Worker 中的离散事件内核，不阻塞界面
- 无需后端，浏览器本地运行，草稿自动保存到 localStorage

## 三、通用操作说明

在进入具体实验之前，先熟悉通用操作：

1. **选择场景**：点击左侧“实验场景”中的一项，程序会自动载入拓扑和业务并运行。
2. **切换问题/修复**：顶部栏的下拉框用于切换每个场景的“问题配置”和“修复配置”。
3. **运行实验**：切换配置后点击右上角 **“运行实验”**（配置改动后会显示“运行新配置”）。
4. **看动画**：拓扑中的圆点是抽样报文，橙色是 ECN 标记、紫色是 CNP、红色是 PFC。
5. **看曲线**：中间下方可以切换 **吞吐 / 队列 / 时延** 三种曲线；点击曲线可跳转时间。
6. **看事件**：右侧事件列表可按 ECN / CNP / PFC / 丢包 过滤，点击事件跳转到发生时刻。
7. **调时间**：拖动时间轴，或使用 0.1×–100× 播放速度。低速适合观察瞬时微突发，高速适合跑完长实验。
8. **看单条链路**：点击拓扑中的链路，曲线会切换为该链路的速率和队列。
9. **看设备配置**：点击节点，在右侧“属性”查看/修改；切到“CLI”可用命令行配置，二者双向同步。

## 四、实验场景 Step by Step

三个场景都遵循同一思路：**先复现故障，再切换修复配置，对比同一业务下的结果。**

### 实验 1：PFC 未开启导致丢包与重传

**目标**：理解 PFC 如何按优先级逐跳反压，在缓冲耗尽前暂停上游，避免 RoCE 丢包和 RTO 重传。

**操作步骤：**

1. 左侧点击 **「PFC 丢包与修复」**，顶部下拉框默认是 **「问题：端口 PFC 未开启」**。
2. 点击右上角 **「运行实验」**，等待计算完成。
3. 观察中间下方指标卡片：
   - **丢包 / 重传** 明显大于 0（典型约 4557 次丢包、215 次重传）。
   - **P95 操作时延** 较高（典型约 30.8 ms）。
4. 在右侧事件列表选择 **“丢包”** 过滤，点击事件跳转，看时间轴上的红色丢包标记。
5. 将顶部下拉框切换为 **「修复：开启 PFC」**，再次点击 **「运行实验」**。
6. 对比结果：
   - **丢包 / 重传 = 0**，业务零丢失完成。
   - P95 时延下降到约 **1.3 ms**。
7. 在事件列表选择 **“PFC”**，可以看到修复后的结果里出现了大量 PFC 暂停/恢复事件（拓扑上红色报文）。

**结论**：PFC 是缓冲耗尽前的最后保护，开启后能在丢包前暂停上游，避免 RoCE 依赖 RTO 重传。

---

### 实验 2：共享内存与尾丢水线（dynamic / static）

**目标**：理解交换机共享内存不足时，dynamic 水线会随剩余空间收紧导致尾丢，而 static 固定水线能让端口吸收同一轮微突发。

**操作步骤：**

1. 左侧点击 **「Dynamic / Static 水线」**，默认是 **「问题：shared dynamic」**。
2. 点击 **「运行实验」**。
3. 观察：
   - **丢包 / 重传** 大于 0（典型约 626 次丢包、32 次重传）。
   - 右侧事件列表选择 **“丢包”**，事件文案会显示 `shared dynamic 尾丢水线 … 已超出`。
4. 切换到 **「修复：static 水线」**，再次运行。
5. 对比：
   - **丢包 / 重传 = 0**。
   - **队列高水位** 明显升高（典型约 3.1 MB），说明共享内存吸收了同一轮突发。
6. 可点击拓扑中的 Spine/Leaf，在右侧“属性 → 交换机与缓冲”里查看 `static 水线` 和 `dynamic Alpha` 的取值。

**结论**：static 水线不是增加物理内存，而是允许端口在突发期间占用更多共享缓冲；若突发持续超过出口能力，再大的水线也只能延迟丢包。

---

### 实验 3：ECN 水线过低放大微突发时延

**目标**：理解 ECN 水线设置过低会让 DCQCN 频繁降速、链路利用率不足，从而放大 NFS 操作时延；提高水线后在不丢包的前提下恢复吞吐。

**操作步骤：**

1. 左侧点击 **「ECN 水线与时延」**，默认是 **「问题：ECN 8–32 KiB」**。
2. 点击 **「运行实验」**（本场景仿真时长较长，约 500 ms，请稍候）。
3. 观察：
   - **ECN / CNP** 计数很大（典型 ECN 约 3029、CNP 约 2720）。
   - **P95 操作时延** 很高（典型约 **111 ms**）。
   - **当前 Goodput** 很低（典型约 4.66G，链路利用率不足）。
4. 把曲线切换到 **“时延”**，可以看到各条 NFS 流的时延曲线长期维持在高位。
5. 切换到 **「修复：ECN 1024–2048 KiB」**，再次运行。
6. 对比：
   - **ECN / CNP** 大幅下降（典型 ECN 约 143）。
   - **P95 操作时延** 下降到约 **19.1 ms**。
   - **当前 Goodput** 上升到约 **76.3G**。
   - 全程 **丢包 / 重传 = 0**，说明业务本身没有因丢包重传，只是被过度降速拖慢。

**结论**：ECN 水线不是越低越好；过低会过早触发降速、浪费带宽。需要同时观察 ECN 次数、P95 时延、队列和丢包，找到合适区间。

## 五、进阶：CE 风格 CLI

选中交换机后，右侧切到 **CLI** 页签，可以像配置真实设备一样操作，改动会同步到图形面板。

```text
display current-configuration
display dcb
display qos queue statistics

dcb ecn enable
ecn priority 3 low-limit 64 high-limit 256 probability 1

dcb pfc enable
priority 3 pfc enable
pfc xoff 256 xon 96

buffer port 512
buffer shared 8192
buffer tail-drop dynamic alpha 0.01
buffer tail-drop static 16384
```

接口配置：

```text
display interface
interface 100GE0/0/9
rate 100
undo shutdown
```

服务器 NIC：

```text
dcqcn enable
dcqcn alpha 0.2
dcqcn min-rate 1 max-rate 100
dcqcn recovery-interval 50
roce priority 3
priority 3 pfc enable
```

输入 `help` 查看完整教学子集。

## 七、模型边界

- 使用聚合帧和离散事件控制浏览器计算量；动画中的报文是抽样轨迹，不是每个真实报文。
- ECN 按教学队列门限概率标记，CNP 和 DCQCN 保留核心因果与节奏，但不追求 bit 级协议一致。NIC 没有独立 ECN 面板，服务器到 Leaf 的 NIC 出口借用对端 Leaf 的 ECN 门限。
- PFC 按优先级逐跳反压，保留 XOFF/XON 迟滞；由排队端口占用驱动上游暂停，不复刻具体芯片流水线。启用 PFC 的无损优先级网卡在暂停期间由主机侧反压，避免在小型 NIC 硬件队列中尾丢。
- 丢包后的 RTO 会重传整个 NFS 操作，不是真实 NFS/RDMA 选择性重传；重复数据不会重复计入 Goodput。
- ECMP 为确定性逐流哈希，不包含 BGP、EVPN、STP、ARP 或真实 RoCE 连接协商。
- 固定业务模板用于教学，不实现真实文件系统、NFS 文件句柄或 Linux 存储栈。
- 为保证浏览器响应，内核会限制调度事件、指标帧、关键事件和轨迹数量；图表与事件时间轴在此基础上进一步抽样展示。
